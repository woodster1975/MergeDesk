Draft checks use an in-process HTTP handler and fake account connector. They verify To/CC/BCC, subject, HTML/plain text, attachment bytes, upload chunk ranges, authentication headers, no send endpoint, missing/oversized files, known rejections, uncertain writes, partial drafts, cancellation, journaling before writes, history compatibility, WPF window construction, confirmation, validation gating, provider changes and connection settings persistence.

Live classic Outlook automation, Microsoft authentication/consent, mailbox synchronization, organization policy and final message rendering require acceptance testing on the intended computer/account. Windows 10 and other CPU architectures have not been separately tested in this environment.

Sending checks cover preparation/submission order, final confirmation, starter-text validation, Email-only source data, cancellation before send and during pacing, draft reuse, confirmed-send skips after restart, concurrent SQLite claims, content/attachment identities, an interrupted submitting marker, authentication rejection, Microsoft HTTP 202/401/429/503, Retry-After at both draft and submission stages, and refusal to submit when the durable state cannot be saved. Microsoft HTTP and desktop sending are simulated; direct sending still needs a small live acceptance test.
